# curveFit vs SciPy `curve_fit` Benchmark Results

Reference: `scipy.optimize.curve_fit(method="lm")` (MINPACK), with
`ftol = xtol = 1.49012e-8` and `gtol = 0`. numerics-js uses the same tolerances
and finite-difference Jacobians in both cases, and its default `jacFinal: false`,
so that, like SciPy, it computes the covariance from the Jacobian of the last
iteration. The fixture stores the data
(`xdata`, `ydata`, `sigma`) generated by the Python script, so the TypeScript
test does not mirror any noise generator; it only mirrors the six model
functions, which are verified against the Python ones at generic parameter
values within `MIRROR_TOLERANCE = 1e-12`.

The cases cover unweighted fits (exponential decay with offset, Gaussian peak,
power law), relative weights (logistic curve, Michaelis-Menten), and absolute
weights (straight line, `absoluteSigma = true`).

The test checks the parameters (relative `1e-6`), the weighted residual sum of
squares (relative `1e-9`), the fitted curve (`1e-7` relative to the data
scale), the degrees of freedom, and the covariance matrix and standard errors
(`COV_TOLERANCE = 1e-6`, entries scaled by `sqrt(cov_ii * cov_jj)`).

Observed maximum relative deviations from SciPy:

| Case                    | Parameters | Standard errors | Covariance (scaled) | numerics-js evaluations | SciPy evaluations |
| :---------------------- | ----------:| ---------------:| -------------------:| -----------------------:| -----------------:|
| exp_decay               |    9.1e-10 |         1.2e-08 |             2.4e-08 |                      21 |                21 |
| gauss                   |    4.4e-11 |         7.8e-09 |             2.1e-08 |                      25 |                25 |
| logistic_sigma          |    3.4e-10 |         6.8e-09 |             1.4e-08 |                      37 |                37 |
| line_absolute_sigma     |    1.1e-08 |         5.9e-08 |             1.2e-07 |                      10 |                10 |
| michaelis_menten_sigma  |    8.3e-10 |         1.4e-08 |             2.8e-08 |                      16 |                16 |
| power_law               |    1.0e-09 |         1.1e-08 |             2.3e-08 |                      24 |                24 |

The parameters agree to the solvers' tolerances, and so does the covariance:
both solvers compute it from the Jacobian of the last iteration, so the two
agree to `1e-7` or better, and the evaluation counts are identical in all cases.

That Jacobian is evaluated one step before the solution, which is a small
systematic error of the covariance. For `exp_decay`, SciPy's `pcov` deviates by
`1.45e-5` from the exact covariance (analytic Jacobian at SciPy's own
solution). With the option `jacFinal: true`, numerics-js recomputes the
Jacobian at the solution, at the cost of `n` extra evaluations (`n = 2` or `3`
here), and its covariance differs from the analytic-Jacobian result by only
`1.8e-8`; in that case, the deviation from SciPy's covariance is up to
`1.5e-5` (and the standard errors differ by up to `7.3e-6`), which is SciPy's
own error.
