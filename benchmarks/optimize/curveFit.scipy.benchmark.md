# curveFit vs SciPy `curve_fit` Benchmark Results

Reference: `scipy.optimize.curve_fit(method="lm")` (MINPACK), with
`ftol = xtol = 1.49012e-8` and `gtol = 0`. numerics-js uses the same tolerances
and finite-difference Jacobians in both cases. The fixture stores the data
(`xdata`, `ydata`, `sigma`) generated by the Python script, so the TypeScript
test does not mirror any noise generator; it only mirrors the six model
functions, which are verified against the Python ones at generic parameter
values within `MIRROR_TOLERANCE = 1e-12`.

The cases cover unweighted fits (exponential decay with offset, Gaussian peak,
power law), relative weights (logistic curve, Michaelis-Menten), and absolute
weights (straight line, `absoluteSigma = true`).

The test checks the parameters (relative `1e-6`), the weighted residual sum of
squares (relative `1e-9`), the fitted curve (`1e-7` relative to the data
scale), the degrees of freedom, and the covariance matrix and standard errors
(`COV_TOLERANCE = 1e-4`, entries scaled by `sqrt(cov_ii * cov_jj)`).

Observed maximum relative deviations from SciPy:

| Case                    | Parameters | Standard errors | Covariance (scaled) | numerics-js evaluations | SciPy evaluations |
| :---------------------- | ----------:| ---------------:| -------------------:| -----------------------:| -----------------:|
| exp_decay               |    9.1e-10 |         7.3e-06 |             1.5e-05 |                      24 |                21 |
| gauss                   |    4.4e-11 |         1.3e-08 |             2.5e-08 |                      28 |                25 |
| logistic_sigma          |    3.4e-10 |         5.0e-06 |             1.0e-05 |                      40 |                37 |
| line_absolute_sigma     |    1.1e-08 |         5.5e-08 |             1.1e-07 |                      12 |                10 |
| michaelis_menten_sigma  |    8.3e-10 |         5.6e-06 |             1.1e-05 |                      18 |                16 |
| power_law               |    1.0e-09 |         2.9e-07 |             5.8e-07 |                      26 |                24 |

The parameters agree to the solvers' tolerances. The covariance agrees to about
`1e-5`, which is not a numerical-noise level but a systematic difference:
SciPy's `pcov` is computed from the Jacobian of the last iteration, evaluated
one step before the solution. For `exp_decay`, `pcov` deviates by `1.45e-5` from
the exact covariance (analytic Jacobian at SciPy's own solution), whereas the
covariance of numerics-js, which recomputes the Jacobian at the solution,
differs from the analytic-Jacobian result by `1.8e-8`.

numerics-js evaluations include the `n` evaluations of the final Jacobian
(`n = 2` or `3` here), which SciPy does not need because it reuses the last
one; subtracting them, the counts are identical.
